# Publishing Auralis on Google Play

The Play Store app is a **Trusted Web Activity (TWA)**: a small Android app, generated by Google's Bubblewrap tool, that opens
`https://auralis-ebon.vercel.app` full screen. Game updates ship by deploying the website as usual; the Android app only
needs a new build when its name, icon, colours or package settings change.

Already in the repo:

| File | What it's for |
|---|---|
| `public/manifest.webmanifest` | App name, colours, icons (including the maskable one Android crops into a circle) |
| `public/icon-maskable-512.png` | Launcher icon with safe padding |
| `public/sw.js`, `public/offline.html` | Friendly "You're offline" page instead of a browser error |
| `public/privacy.html` | Privacy policy (Play requires a URL) |
| `public/.well-known/assetlinks.json` | Proves the site and the app belong together, so the app shows no browser bar |
| `android/twa-manifest.json` | Bubblewrap settings (package name, colours, icons, version) |

## 1. Before you build

1. **Pick the package name for good.** It's `com.auralis.app` in `android/twa-manifest.json` and in
   `public/.well-known/assetlinks.json`. Once an app is published under a package name it can never change, so set the one
   you want in both files now (for example `com.yourname.auralis`).
2. **Add your contact email** to `public/privacy.html` (two highlighted spots).
3. **Deploy the site** (push to the branch Vercel builds), then check these open:
   - https://auralis-ebon.vercel.app/manifest.webmanifest
   - https://auralis-ebon.vercel.app/privacy.html
   - https://auralis-ebon.vercel.app/.well-known/assetlinks.json

## 2. Build the Android app

You need Node.js. Bubblewrap offers to download the Java JDK and Android SDK it needs on first run; say yes.

```bash
cd android
npx @bubblewrap/cli init --manifest=https://auralis-ebon.vercel.app/manifest.webmanifest
```

Answer the prompts with the values from `twa-manifest.json` (domain `auralis-ebon.vercel.app`, your package name,
app name `Auralis`, colours `#efe6da`, version 1). When it asks about a signing key, let it **create a new keystore**
(`android.keystore`, alias `android`) and choose passwords.

> **Keep `android.keystore` and its passwords safe and backed up outside the repo.** It's your upload key; it's
> already git-ignored. If you lose it you'll need Google support to reset it.

Then build:

```bash
npx @bubblewrap/cli build
```

This makes `app-release-bundle.aab` (upload this to Play) and `app-release-signed.apk` (install on your own phone to try it).

## 3. Connect the site to the app (asset links)

Without this the app still works, but shows a browser address bar at the top.

1. Get your **upload key** fingerprint:
   ```bash
   keytool -list -v -keystore android.keystore -alias android
   ```
   Copy the `SHA256:` line.
2. After your first upload to Play (step 4), open **Play Console → your app → Test and release → App integrity →
   App signing** and copy the **App signing key certificate SHA-256**. Google re-signs the app with this key, so it's the
   one phones actually see.
3. Put both into `public/.well-known/assetlinks.json` in place of the two `REPLACE_WITH_…` values, then deploy the site.
4. Check it with Google's tool: https://developers.google.com/digital-asset-links/tools/generator

## 4. Play Console

1. Create a developer account (one-time $25) at https://play.google.com/console and **Create app**:
   name Auralis, app (not game), free.
2. **New personal accounts must run a closed test first:** at least 12 testers opted in for 14 days in a row before you can
   apply for production. Upload the `.aab` to a closed testing track and invite friends.
3. **Store listing**:
   - **Short description** (≤ 80 characters):
     `Study with friends in a cozy pixel house. Focus, earn coins, decorate.`
   - **Full description** (draft):
     > Auralis turns studying into a cozy little house you share with friends. Start a focus session and your pixel
     > buddy sits at their desk until the timer ends: every focused minute earns a coin. Study at the same time as
     > housemates for a bigger bonus, run Pomodoro breaks, count down to exams and keep shared to-dos and a house calendar.
     >
     > Spend your coins on hundreds of pieces of furniture, plants, pets and festive decorations, then arrange your room
     > however you like. Friends' rooms join yours into one big house where you can chat, cheer each other on, leave notes
     > on desks and watch videos together.
   - **App icon**: `public/icon-512.png`.
   - **Feature graphic** (1024 × 500, required): make one in any image editor, for example the icon on the beige
     background beside the name "Auralis" and a room screenshot. Keep text minimal.
   - **Phone screenshots** (at least 2): take them on your phone in the app: your room, a focus session, the shop.
4. **App content**:
   - **Privacy policy**: `https://auralis-ebon.vercel.app/privacy.html`
   - **Ads**: no ads.
   - **Account deletion URL**: `https://auralis-ebon.vercel.app/privacy.html#delete`. Play requires apps with accounts to
     let people request deletion; right now that's by email, which you'd handle by hand.
   - **Target audience**: 13 and over (the policy says the app isn't for under-13s). Choosing younger ages brings in
     Google's Families rules.
   - **Content rating**: fill in the questionnaire honestly. Answer yes to *users can interact/communicate with each
     other* (chat, private messages, notes) and *users can share content*.
   - **Data safety** (draft answers, based on what the server actually stores):

     | Data type | Collected | Why | Required |
     |---|---|---|---|
     | Personal info → Email address | Yes | Account management | Yes |
     | Personal info → User IDs (username) | Yes | Account management, app functionality | Yes |
     | Messages → Other in-app messages (house chat, private messages, desk notes) | Yes | App functionality | No |
     | App activity → App interactions (focus sessions, coins, purchases in the game) | Yes | App functionality | Yes |
     | App activity → Other user-generated content (to-dos, calendar, exam dates, room snapshots) | Yes | App functionality | No |

     - Data shared with third parties: **No** (Neon, Render and Vercel are service providers processing data for you,
       which Play doesn't count as sharing).
     - Encrypted in transit: **Yes**.
     - Users can request deletion: **Yes** (by email, see the policy).
     - No location, contacts, photos from the device, payment info, device IDs, analytics or ads data.

## 5. Updating later

- **Game changes**: deploy the website. The app picks them up on next launch; no new upload needed.
- **App changes** (icon, name, colours, package settings): edit `android/twa-manifest.json`, raise `appVersionCode` by 1
  (and `appVersionName`), run `npx @bubblewrap/cli update` then `npx @bubblewrap/cli build`, and upload the new `.aab`.
